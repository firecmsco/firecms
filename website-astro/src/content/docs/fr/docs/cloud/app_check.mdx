FireCMS Cloud peut imposer Firebase App Check sur chaque requête que votre panneau d'administration envoie à Firestore et Storage, afin que seul votre propre CMS puisse lire ou écrire vos données, et non une clé d'API copiée ou un script extrait de votre bundle.

App Check est un service Firebase. Cette page explique comment l'intégrer à FireCMS ; pour savoir ce que fait App Check et quels fournisseurs d'attestation existent, consultez [la documentation App Check de Firebase](https://firebase.google.com/docs/app-check).

:::important
N'oubliez pas d'ajouter le domaine `app.firecms.co` à la liste des domaines autorisés dans la configuration du fournisseur AppCheck.
:::

Vous pouvez activer Firebase App Check dans votre application directement dans les **paramètres du projet** dans la console FireCMS Cloud,
ou en fournissant la prop `appCheck` dans la configuration de votre application.

En l'implémentant dans le code, vous pouvez avoir plus de contrôle sur la configuration et le fournisseur que vous souhaitez utiliser,
y compris des fournisseurs personnalisés.

Vous pouvez définir certaines options :
- `provider` : Le fournisseur que vous souhaitez utiliser.
- `isTokenAutoRefreshEnabled` : Si le token doit être automatiquement renouvelé.
- `debugToken` : Un token de débogage à utiliser.
- `forceRefresh` : Si un renouvellement de token doit être forcé.


## Fournisseurs

La propriété `provider` est requise et doit être une instance d'un fournisseur Firebase AppCheck.
Vous pouvez utiliser l'un des fournisseurs suivants :

### ReCaptchaEnterpriseProvider

Pour configurer le ReCaptchaEnterpriseProvider, vous devez créer une nouvelle clé de site reCAPTCHA Enterprise.
Suivez les instructions dans la [documentation Firebase](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider).

:::important
Assurez-vous d'avoir ajouté le domaine `app.firecms.co` à la liste des domaines autorisés dans la console reCAPTCHA Enterprise.
:::

```tsx
import {FireCMSAppConfig} from "@firecms/cloud";
import {ReCaptchaEnterpriseProvider} from "@firebase/app-check";

const appConfig: FireCMSAppConfig = {

    version: "1",

    appCheck: {
        provider: new ReCaptchaEnterpriseProvider("your-site-key")
    },
}

export default appConfig;
```

### ReCaptchaV3Provider

Pour configurer le ReCaptchaV3Provider, vous devez créer une nouvelle clé de site reCAPTCHA v3.
Suivez les instructions dans la [documentation Firebase](https://firebase.google.com/docs/app-check/web/recaptcha-provider).

```tsx
import {FireCMSAppConfig} from "@firecms/cloud";
import {ReCaptchaV3Provider} from "@firebase/app-check";

const appConfig: FireCMSAppConfig = {

    version: "1",

    appCheck: {
        provider: new ReCaptchaV3Provider("your-site-key")
    },
}

export default appConfig;
```

### Fournisseur personnalisé

Vous pouvez également créer un fournisseur personnalisé en implémentant l'interface `AppCheckProvider`.


## Vérifier votre configuration

FireCMS Cloud fournit Firebase App Check à votre code : le provider que vous créez utilise donc la
même copie du SDK que FireCMS lui-même. Deux choses sont nécessaires :

- **Importez depuis `@firebase/app-check`**, comme dans les exemples ci-dessus, et non depuis
  `firebase/app-check`. Seuls les imports qui nomment exactement un package partagé reçoivent la
  copie de FireCMS. Un import depuis `firebase/app-check` fait pointer le build vers un fichier qu'il
  ne produit jamais, et l'application affiche "Error loading remote config".
- **Gardez `@firebase/app-check` dans la section `shared`** du plugin de federation de votre
  `vite.config.ts`. Le modèle FireCMS Cloud l'inclut déjà.

La section `shared` du modèle ressemble à ceci. `generate: false` signifie que votre build n'embarque
aucune copie du package et utilise celle que fournit FireCMS :

```ts
federation({
    name: "remote_app",
    filename: "remoteEntry.js",
    exposes: {
        "./config": "./src/index"
    },
    shared: {
        "react": { generate: false },
        "react-dom": { generate: false },
        "react/jsx-runtime": { generate: false },
        "react/jsx-dev-runtime": { generate: false },
        "@firecms/cloud": { generate: false },
        "@firecms/core": { generate: false },
        "@firecms/firebase": { generate: false },
        "@firecms/ui": { generate: false },
        "@firebase/firestore": { generate: false },
        "@firebase/app": { generate: false },
        "@firebase/functions": { generate: false },
        "@firebase/auth": { generate: false },
        "@firebase/storage": { generate: false },
        "@firebase/analytics": { generate: false },
        "@firebase/remote-config": { generate: false },
        "@firebase/app-check": { generate: false },
    }
})
```

Pour le fichier complet, consultez le
[`vite.config.ts` du modèle FireCMS Cloud](https://github.com/firecmsco/firecms/blob/main/packages/cli/templates/template_cloud/vite.config.ts).
