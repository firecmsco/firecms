FireCMS Cloud bringt einen **MCP-Server** mit, damit KI-Assistenten wie Claude Code, Claude Desktop
oder Cursor direkt an deinem Projekt arbeiten können: Daten durchsuchen und bearbeiten, Kollektionen
anlegen und ändern, Schemata aus den bereits vorhandenen Firestore-Dokumenten ableiten und Benutzer
verwalten.

Er wird als [`@firecms/mcp-server`](https://www.npmjs.com/package/@firecms/mcp-server) veröffentlicht
und läuft lokal auf deinem Rechner über stdio. Er spricht mit der FireCMS-Cloud-API unter deinem
eigenen Konto — ein Agent kann also nie etwas tun, was du nicht auch selbst in der Konsole tun könntest.

## Voraussetzungen

- **Node.js 18** oder neuer.
- Ein **MCP-fähiger Client**: Claude Code, Claude Desktop, Cursor oder ein anderer Client,
  der das Model Context Protocol spricht.
- Ein **FireCMS-Cloud**-Konto. Lesen kann jedes Projektmitglied; das Anlegen oder Ändern von
  Kollektionen, Daten und Benutzern erfordert die Rolle `admin` im Projekt.

## Den FireCMS MCP-Server hinzufügen

Führe in **Claude Code** dies in deinem Terminal aus:

```bash
claude mcp add firecms -- npx -y @firecms/mcp-server
```

Für **Claude Desktop**, **Cursor** oder jeden anderen MCP-Client fügst du das hier in die
MCP-Konfigurationsdatei des Clients ein:

```json
{
  "mcpServers": {
    "firecms": {
      "command": "npx",
      "args": ["-y", "@firecms/mcp-server"]
    }
  }
}
```

Wo diese Datei liegt:

- **Claude Desktop**: `claude_desktop_config.json`
- **Cursor**: `.cursor/mcp.json` in deinem Projekt oder `~/.cursor/mcp.json` für alle Projekte

## Anmelden

Starte deinen Client neu und bitte den Agenten, das Tool `firecms_login` auszuführen:

```
Run the firecms_login tool
```

Es öffnet einen Browser für die Google-Anmeldung und legt die Zugangsdaten in
`~/.firecms/tokens.json` ab — dieselbe Datei, die auch die
[FireCMS CLI](https://www.npmjs.com/package/@firecms/cli) verwendet. Das ist nur einmal nötig;
spätere Sitzungen greifen automatisch auf die Tokens zu.

Mit `firecms_get_current_user` siehst du, als wer du angemeldet bist, mit `firecms_logout` meldest
du dich ab.

## Ausprobieren

Bitte den Agenten um so etwas:

```
List my FireCMS projects
```

```
List the collections in my FireCMS project <deine-project-id>
```

```
Add a "featured" boolean property to the products collection, shown after the title
```

## Ein bestehendes Firebase-Projekt einbinden

Das ist die typische erste Sitzung. Alles hier läuft über das Google-Konto, mit dem du dich
angemeldet hast:

1. `list_firebase_projects` — zeigt, welche Projekte du verbinden kannst und was ihnen noch fehlt
2. `get_project_setup_status` — ein Projekt im Detail prüfen (optional)
3. `enable_project_apis` — nur wenn `apisEnabled` false ist
4. `enable_firestore` — nur wenn `firestoreEnabled` false ist (der Standort ist dauerhaft)
5. `connect_project_to_firecms` — Dienstkonto, Admin-Benutzer und die Sicherheitsregeln
6. `setup_all_collections` — leitet jede Root-Kollektion aus den vorhandenen Daten ab

:::caution
**Firebase Authentication** muss im Projekt aktiviert sein, bevor Schritt 5 läuft. Es ist die einzige
Voraussetzung ohne API dahinter — schalte sie also zuerst in der Firebase-Konsole ein.
:::

Schritt 5 fügt außerdem die Zugriffsregel von FireCMS zu den Firestore- und Storage-Regeln des
Projekts hinzu. Ohne sie meldet das CMS *Missing Firestore Security Rules* und öffnet gar nichts.
Falls du sie später erneut anwenden musst: `apply_firestore_security_rules` ist idempotent.

In Schritt 6 wird aus einem bestehenden Projekt ein funktionierendes CMS: FireCMS nimmt Stichproben
der Dokumente jeder Root-Kollektion, leitet die Property-Typen ab und wählt Anzeigenamen, einen
Singular-Namen, ein Icon und eine Navigationsgruppe.

## Kollektionen aus vorhandenen Daten aufbauen

| Tool | Beschreibung |
|------|-------------|
| `get_root_collections` | Listet die Firestore-Root-Kollektionen eines Projekts (live gelesen) |
| `list_subcollections` | Listet die Subkollektionen eines Dokuments, um verschachtelte Daten zu erkunden |
| `list_databases` | Listet Firestore-Datenbanken (nur nötig über `(default)` hinaus) |
| `preview_inferred_schema` | Leitet ein Schema aus Stichproben ab, **ohne es zu speichern** |
| `infer_collections_from_data` 🔒 | Leitet Kollektionen für ausgewählte Pfade ab und speichert sie |
| `setup_all_collections` 🔒 | Leitet jede noch nicht zugeordnete Root-Kollektion ab und speichert sie |

`preview_inferred_schema` ist die zerstörungsfreie Variante: Es nimmt Stichproben von bis zu 200
Dokumenten, leitet Typen, Enums und Validierungen ab und gibt einen Entwurf zurück, den du
bearbeiten und anschließend mit `save_collection_schema` persistieren kannst. Es funktioniert auch
für Subkollektionen und für jeden Pfad, den die Massen-Tools überspringen.

`infer_collections_from_data` und `setup_all_collections` schreiben das Ergebnis direkt ins Projekt.
Beide überspringen Pfade, die bereits einer Kollektion zugeordnet sind, und lassen sich daher
gefahrlos erneut ausführen, wenn deine Datenbank wächst. Pfade ohne Dokumente lehnen sie ab: Ohne
etwas zum Auswerten würde ein Modell ein Schema allein aus dem Pfadnamen erfinden.

Mit 🔒 markierte Tools erfordern die Rolle `admin` im Projekt.

### Authentifizierung

| Tool | Beschreibung |
|------|-------------|
| `firecms_login` | Anmeldung über den Browser (Google OAuth) |
| `firecms_logout` | Abmelden |
| `firecms_get_current_user` | Zeigt den aktuellen Benutzer |

### Onboarding

| Tool | Beschreibung |
|------|-------------|
| `list_firebase_projects` | Google-Cloud-Projekte mit Zugriff, samt FireCMS-Bereitschaftsstatus |
| `get_project_setup_status` | Detaillierter Bereitschaftsstatus eines Projekts |
| `list_firestore_locations` | Verfügbare Standorte für eine neue Firestore-Datenbank |
| `enable_project_apis` | Aktiviert die von FireCMS benötigten Google-Cloud-APIs |
| `enable_firestore` | Legt die Standard-Firestore-Datenbank an (der Standort ist dauerhaft) |
| `connect_project_to_firecms` | Verbindet ein bestehendes Firebase-Projekt und wendet die nötigen Sicherheitsregeln an |
| `apply_firestore_security_rules` | Fügt die FireCMS-Zugriffsregel zu Firestore und Storage hinzu (idempotent) |
| `create_firecms_webapp` | Wiederholt die Erstellung der Web-App, falls sie beim Verbinden fehlschlug |

Clients mit Unterstützung für MCP-Ressourcen können diese auch direkt lesen:

| URI | Beschreibung |
|-----|-------------|
| `firecms://projects/{id}/collections` | Firestore-Kollektionen auf oberster Ebene |

## Berechtigungen und Sicherheit

- Die **Authentifizierung** läuft über Google OAuth im Browser — derselbe Ablauf wie `firecms login` in der CLI.
- Die **Autorisierung** wird pro Projekt geprüft: Jeder Schreibvorgang erzwingt die Rolle `admin`.
- Die **Tokens** liegen in `~/.firecms/tokens.json`, gemeinsam mit der CLI. Das Backend-Token wird nur
  im Speicher gehalten und beim Abmelden verworfen.
- **Zugangsdaten erreichen das Modell nie**: `list_projects` entfernt das Dienstkonto jedes Projekts
  aus seiner Ausgabe.

## Fehlerbehebung

**Der Agent sagt, du seist nicht angemeldet.** Führe das Tool `firecms_login` aus. Öffnet sich kein
Browserfenster, führe `npx @firecms/mcp-server --help` im Terminal aus, um zu prüfen, ob das Paket
installiert wird und startet.

**Die Tools erscheinen nach dem Bearbeiten der Konfiguration nicht.** MCP-Clients lesen ihre
Konfiguration beim Start — starte den Client vollständig neu.

**Ein Schreibvorgang scheitert an fehlenden Berechtigungen.** Das Konto, mit dem du angemeldet bist,
braucht die Rolle `admin` in diesem Projekt. Prüfe das im Bereich *Benutzer* des Projekts in
[FireCMS Cloud](https://app.firecms.co) oder bitte eine Administratorin oder einen Administrator darum.

**Nach dem Verbinden eines Projekts erscheinen keine Kollektionen.** Stelle sicher, dass Firebase
Authentication aktiviert ist und die Sicherheitsregeln angewendet wurden
(`apply_firestore_security_rules`), und führe dann `setup_all_collections` aus.
