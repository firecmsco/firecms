FireCMS Cloud kann Firebase App Check bei jeder Anfrage erzwingen, die dein Admin-Panel an Firestore und Storage stellt, sodass nur dein eigenes CMS deine Daten lesen oder schreiben kann — kein kopierter API-Schlüssel und kein aus deinem Bundle extrahiertes Skript.

App Check ist ein Firebase-Dienst. Diese Seite beschreibt die Einbindung in FireCMS; was App Check leistet und welche Attestierungsanbieter es gibt, steht in [Firebases eigener App-Check-Dokumentation](https://firebase.google.com/docs/app-check).

:::important
Denken Sie daran, die Domain `app.firecms.co` zur Liste der erlaubten Domains in der AppCheck-Anbieter-Konfiguration hinzuzufügen.
:::

Sie können Firebase App Check in Ihrer Anwendung direkt in den **Projekteinstellungen** in der FireCMS Cloud-Konsole aktivieren oder die Eigenschaft `appCheck` in der App-Konfiguration bereitstellen.

Bei der Implementierung im Code haben Sie mehr Kontrolle über die Konfiguration und den Anbieter, den Sie verwenden möchten, einschließlich benutzerdefinierter Anbieter.

Sie können einige Optionen definieren:
- `provider`: Der Anbieter, den Sie verwenden möchten.
- `isTokenAutoRefreshEnabled`: Ob das Token automatisch aktualisiert werden soll.
- `debugToken`: Ein Debug-Token zur Verwendung.
- `forceRefresh`: Ob das Token erzwungen aktualisiert werden soll.


## Anbieter

Die Eigenschaft `provider` ist erforderlich und muss eine Instanz eines Firebase AppCheck-Anbieters sein.
Sie können einen der folgenden Anbieter verwenden:

### ReCaptchaEnterpriseProvider

Um den ReCaptchaEnterpriseProvider zu konfigurieren, müssen Sie einen neuen reCAPTCHA Enterprise-Site-Schlüssel erstellen.
Folgen Sie den Anweisungen in der [Firebase-Dokumentation](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider).

:::important
Stellen Sie sicher, dass Sie die Domain `app.firecms.co` zur Liste der erlaubten Domains in der reCAPTCHA Enterprise-Konsole hinzugefügt haben.
:::

```tsx
import {FireCMSAppConfig} from "@firecms/cloud";
import {ReCaptchaEnterpriseProvider} from "@firebase/app-check";

const appConfig: FireCMSAppConfig = {

    version: "1",

    appCheck: {
        provider: new ReCaptchaEnterpriseProvider("Ihr-Site-Schlüssel")
    },
}

export default appConfig;
```

### ReCaptchaV3Provider

Um den ReCaptchaV3Provider zu konfigurieren, müssen Sie einen neuen reCAPTCHA v3-Site-Schlüssel erstellen.
Folgen Sie den Anweisungen in der [Firebase-Dokumentation](https://firebase.google.com/docs/app-check/web/recaptcha-provider).

```tsx
import {FireCMSAppConfig} from "@firecms/cloud";
import {ReCaptchaV3Provider} from "@firebase/app-check";

const appConfig: FireCMSAppConfig = {

    version: "1",

    appCheck: {
        provider: new ReCaptchaV3Provider("Ihr-Site-Schlüssel")
    },
}

export default appConfig;
```

### Benutzerdefinierter Anbieter

Sie können auch einen benutzerdefinierten Anbieter erstellen, indem Sie die Schnittstelle `AppCheckProvider` implementieren.


## Ihrer Konfiguration überprüfen

FireCMS Cloud stellt Ihrem Code Firebase App Check bereit, sodass der von Ihnen erstellte Provider
dieselbe Kopie des SDK verwendet wie FireCMS selbst. Dafür sind zwei Dinge nötig:

- **Importieren Sie aus `@firebase/app-check`**, wie in den Beispielen oben, nicht aus
  `firebase/app-check`. Nur Importe, die ein geteiltes Paket exakt benennen, erhalten die Kopie von
  FireCMS. Ein Import aus `firebase/app-check` lässt den Build auf eine Datei verweisen, die er nie
  erzeugt, und die App zeigt "Error loading remote config".
- **Behalten Sie `@firebase/app-check` im Abschnitt `shared`** des Federation-Plugins in Ihrer
  `vite.config.ts`. Die FireCMS Cloud-Vorlage führt es bereits auf.

Der Abschnitt `shared` der Vorlage sieht so aus. `generate: false` bedeutet, dass Ihr Build keine
Kopie des Pakets enthält und die von FireCMS bereitgestellte verwendet:

```ts
federation({
    name: "remote_app",
    filename: "remoteEntry.js",
    exposes: {
        "./config": "./src/index"
    },
    shared: {
        "react": { generate: false },
        "react-dom": { generate: false },
        "react/jsx-runtime": { generate: false },
        "react/jsx-dev-runtime": { generate: false },
        "@firecms/cloud": { generate: false },
        "@firecms/core": { generate: false },
        "@firecms/firebase": { generate: false },
        "@firecms/ui": { generate: false },
        "@firebase/firestore": { generate: false },
        "@firebase/app": { generate: false },
        "@firebase/functions": { generate: false },
        "@firebase/auth": { generate: false },
        "@firebase/storage": { generate: false },
        "@firebase/analytics": { generate: false },
        "@firebase/remote-config": { generate: false },
        "@firebase/app-check": { generate: false },
    }
})
```

Die vollständige Datei finden Sie in der
[`vite.config.ts` der FireCMS Cloud-Vorlage](https://github.com/firecmsco/firecms/blob/main/packages/cli/templates/template_cloud/vite.config.ts).
